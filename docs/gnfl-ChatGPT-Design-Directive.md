# GNFL ChatGPT向けCG・デザイン指示書

> [!abstract] この文書の目的
> 本文書は、ChatGPTへGNFLのコンセプトアート、港湾背景、CG参考画像、配色、UI外観、視覚効果の設計を依頼するための上位指示書である。ユーザーがCGやアニメーションを手描きすることを前提にしない。ChatGPTは背景とアートディレクションを担当し、CodexまたはGrok Buildは正確な可動SVG、Phaserアニメーション、React UI、ゲームへの組込みを担当する。

実装、物理、Worker、AWS、ランキング、GitHub Actionsの指示は [[implementation-directive]] を参照すること。

---

## 0. この版で確定した制作方針

- 初期工程は船からの荷揚げだけとする。
- 最初から大量の全工程素材を作らない。
- 画風候補を必ず3案作る工程は廃止する。
- まず基準となるmaster conceptを1案作り、会話で修正して確定する。
- ChatGPTは港湾背景、寒冷な曇天、遠景の架空施設、霧、大気感、海面の基準表現を担当する。
- 物理的に動く船、クレーン、トロリー、吊具、輸送容器、搬送台車、受台、計器類はCodex等がSVGで制作する。
- ワイヤー、ガイド線、計器針、風筋、波頭、しぶき、霧粒子、警告点滅はPhaserで描画する。
- タイトル、設定、結果、ランキング画面はReact、CSS、SVGで実装する。
- UIを一枚のAI生成画像として固定しない。
- 画像へ文字、数字、ロゴを焼き込まない。
- オープニング動画、エンディング動画は初期版で作らない。
- 厳密なprovenance YAML、承認日時管理、全asset manifest自動生成を必須にしない。
- Git LFSを初期要件にしない。
- 物理が仮図形で完成してから正式アートへ置き換える。

## 2. 世界観

### 2.1 基本設定

青森県六ヶ所村の寒冷な沿岸工業地域と、大規模な原子燃料サイクル施設を想起させる、完全に架空の工業コンプレックスを舞台とする。

仮の施設名：

```text
Northern Cycle Complex 6
NCC-6
北方燃料サイクルセンター第6地区
```

実装側で別名称へ変更してよい。

### 2.2 雰囲気

- 北方の冷たい海
- 低い雲
- 湿った空気
- 海霧
- 強い海風
- 白、灰、青緑を基調にした工業施設
- 巨大だが整理された設備
- 港湾の重量感
- 遠隔操作と安全管理の緊張感
- 派手なSFではなく、現代から少し先の工業技術

### 2.3 フィクション境界

必ず守ること：

1. 実在する六ヶ所再処理工場の建屋配置を複製しない。
2. 実在港湾の岸壁、道路、警備設備を再現しない。
3. 日本原燃、電力会社、官公庁、船会社、メーカーのロゴを描かない。
4. 実在輸送船、実在輸送容器、実在クレーンを一対一で複製しない。
5. 警備カメラ、フェンス、ゲート等を主題にしない。
6. 実在施設の航空写真をトレースしない。
7. 施設名、船名、装置番号は架空とする。
8. 画像内に実運転値や実寸法を描かない。
9. 写実的な放射線被害、人体被害、漏えいを描かない。
10. 「実在の施設・企業とは関係のないフィクション」と表示できる余白を確保する。

## 4. アートスタイル

### 4.1 一文定義

**寒冷な北方港湾の工業技術イラストを、現代的な2Dゲームとして読みやすく整理した、セミリアルな2.5Dサイドビュー。**

### 4.2 必須要素

- 2D主体
- 横から見た構図
- 正投影に近い弱い遠近感
- 工業設備の重量感
- 曇天の柔らかい拡散光
- 湿度と海風を感じる大気
- 可動部が一目で分かる整理された形
- 写真ではなくイラスト
- 玩具のように丸くしすぎない
- 過度な汚しや廃墟感を避ける
- 現役で整備された施設に見せる

### 4.3 避ける画風

- アニメキャラクター中心
- サイバーパンクのネオン
- 宇宙基地
- 第二次世界大戦風
- 廃墟
- ホラー
- 極端なフォトリアル
- アイソメトリック経営ゲームのような強い俯瞰
- 手描き水彩
- 幼児向けカートゥーン
- 過度なセルシェーディング

### 4.4 線と形

- 外形は明瞭にする。
- 細部を過密にしない。
- クレーン、船倉、受台の接触関係が読み取れることを優先する。
- 背景の線密度は前景より低くする。
- 可動部には周囲より少し強い輪郭または明度差を付ける。
- 物理操作対象のシルエットを背景へ埋没させない。

## 5. カラーパレット

### 5.1 基本色

| 用途           | 色         | Hex目安   |
| -------------- | ---------- | --------- |
| 曇天空         | 青みの灰   | `#7D8A91` |
| 遠景霧         | 明るい灰青 | `#AAB6BA` |
| 海             | 深い青緑   | `#314E5A` |
| 海の反射       | 鈍い青     | `#54717B` |
| 鉄骨           | 中間灰     | `#56636A` |
| 建屋           | 冷たい白   | `#D8DEE0` |
| 設備アクセント | 青緑       | `#4E8B8A` |
| 暗部           | 濃い青灰   | `#1C252B` |
| 安全表示       | 緑         | `#5FA66A` |
| 注意           | 黄橙       | `#E5A936` |
| 警報           | 赤         | `#C94747` |
| ガイド         | 水色       | `#72B8C6` |

Hexは基準であり、最終実装ではコントラストを確認して調整してよい。

### 5.2 色の役割

- 背景は低彩度。
- 操作対象は背景より明度差を付ける。
- 通常状態は青緑、白、灰。
- 注意は黄橙。
- 安全停止や重大警報だけ赤。
- ランキングや結果画面を金色だらけにしない。
- 色だけで状態を伝えず、形、アイコン、点灯、動きも併用する。

## 6. 光と天候

### 6.1 通常光

- 太陽が直接見えない曇天。
- 影は柔らかい。
- 金属のハイライトは控えめ。
- 海面反射は鈍い。
- 作業灯は暖色寄りだが、全画面をオレンジにしない。
- 画面左上または上方から統一した拡散光を想定する。

### 6.2 突風の視覚予兆

画像へ風を固定して描き込まず、Phaserで動かせる余地を残す。

参考表現：

- 遠くの海面に斜めの風筋
- 吹き流しの角度変化
- 薄い霧の流れ
- 海面の一部だけ細かな波が増える
- 吊荷周辺の細い流線

避ける表現：

- 竜巻
- 巨大な衝撃波
- 白い漫画風スピード線だらけ
- カウントダウン文字

### 6.3 高波の視覚予兆

- 遠景から波頭が大きくなる。
- 船体と岸壁の相対高さが少しずつ変わる。
- 海面色を急に変えず、波形の高さと白波を増やす。
- 係留索や船体のきしみは音響で補う。
- 高波本体は数周期の波群として表現する。

### 6.4 霧

- 背景と遠景施設の間に薄い大気遠近を置く。
- 可動物の輪郭を隠すほど濃くしない。
- 霧は静止画像一枚ではなく、Phaserの低速レイヤーを併用する。

## 7. 画面設計

### 7.1 基準解像度

- ゲーム論理解像度：1920×1080
- master conceptと背景制作：2560×1440以上
- PCブラウザ向け
- 16:9を基準とする
- 21:9では横に表示範囲を拡張するか、装飾背景を追加する
- 画面を横方向へ引き伸ばさない

### 7.2 Safe Area

重要な操作対象とUIは中央1600×900相当へ収める。

- 左右端は超横長画面で追加表示されてもよい背景領域とする。
- 上端には最小限の状態表示。
- 下端には操作盤。
- 中央は吊荷、船倉、受台の動線を遮らない。

### 7.3 基本レイアウト

```text
┌──────────────────────────────────────────────┐
│ 曇天・遠景施設・風向表現                         │
│                                                │
│             ガントリークレーン                   │
│        ───── トロリー ─────                   │
│                    │                           │
│                 吊具・容器                      │
│                                                │
│  船・船倉             岸壁          車両受台    │
│  ～～～～～～～～ 海面 ～～～～～～～～～～      │
├──────────────────────────────────────────────┤
│ 張力  振れ  ロック  巻上げ  横行  着座ガイド     │
└──────────────────────────────────────────────┘
```

### 7.4 視線誘導

- 初期位置の船倉を左側。
- 着座先を右側。
- プレイヤーの移動方向が左から右へ自然に読める。
- クレーンの水平レールを視線誘導線として使う。
- 遠景施設は中央操作を邪魔しない低コントラストにする。
- 吊荷と障害物のクリアランスを確認できる余白を確保する。

## 10. CodexがSVGで作るもの

物理的に動く、または正確なpivotが必要なものはAI画像ではなくSVGを基本とする。

### 10.1 初期SVG一覧

```text
ship_body_rear.svg
ship_hold_foreground.svg
crane_gantry.svg
crane_trolley.svg
hoist_unit.svg
spreader.svg
transport_cask.svg
transporter_body.svg
seating_frame_rear.svg
seating_frame_front.svg
windsock.svg
control_lever_horizontal.svg
control_lever_hoist.svg
indicator_lamp.svg
analog_gauge.svg
```

### 10.2 SVGルール

- 正しい`viewBox`を持つ。
- widthとheightへ固定pxだけを埋め込まず、スケーラブルにする。
- テキストを埋め込まない。
- 外部フォントを参照しない。
- 外部画像をbase64埋込みしない。
- 過度に複雑なfilterを使わない。
- 形状グループ名を意味のある英語にする。
- pivot候補をasset noteへ記録する。
- 同じ座標系で前景・後景を分割するassetは共通viewBoxを使用する。
- 物理コライダーはSVG pathから自動生成しない。

### 10.3 船体

船は高波で上下・傾斜するため、背景へ固定しない。

分割：

- 船体後景
- 船倉内部
- 船倉前景マスク

船倉前景マスクは吊荷が内部に入ったように見せるために必要である。

### 10.4 クレーン

分割：

- 固定ガントリー
- レール
- トロリー
- 巻上げ装置
- 吊具

ワイヤーはSVGに含めない。

### 10.5 輸送容器

- 架空設計とする。
- 円筒形または多角柱の重量物。
- 上部に架空の吊点。
- 実在メーカー形状を複製しない。
- 遠距離でも角度と揺れが分かる非対称な小さな目印を付ける。
- 放射線標識を巨大な主役にしない。

## 11. Phaserで動かす表現

### 11.1 ワイヤー

- トロリー吊点から吊具取付点へ線を描く。
- 張力によって色を極端に変えず、計器で状態を伝える。
- たるみがある場合は簡単な曲線表現を使ってよい。
- 物理ケーブルと視覚線の本数を一致させる。

### 11.2 船体

Worker snapshotの位置と角度を船体SVG全体へ適用する。

- 船体後景
- 船倉内部
- 船倉前景

は同じ親Containerへ入れ、同一transformを適用する。

### 11.3 海面

本格流体を使わない。

- 横スクロールする海面texture
- 複数レイヤーの波
- 白波particle
- 船体周辺の控えめなしぶき
- 高波event時の振幅増加

ゲーム判定用の船体運動と、見た目の波を大きく乖離させない。

### 11.4 風

- 風筋は半透明の短い線または粒子。
- 常時大量に表示しない。
- 突風予兆時に密度と速度を増やす。
- 吹き流しの角度をWorkerの風向値と連動する。

### 11.5 計器

- 針式計器はPhaser GraphicsまたはSVGの針回転で実装する。
- 数値を表示する場合もゲーム用正規化値とする。
- 経過時間を表示しない。

## 12. React UIデザイン

### 12.1 Reactで作る画面

- Title
- Stage Start
- Settings
- Result
- Leaderboard
- Error
- Fiction Notice

### 12.2 UI原則

- 画像として一枚に焼き込まない。
- HTML、CSS、SVGを使う。
- 現代的だがゲーム世界から浮かない。
- 大きな角丸カードだらけの一般的SaaS画面にしない。
- 工業操作盤の直線的な区切りを取り入れる。
- ただし古いCRT画面の完全再現にはしない。
- ダークテーマを基調とする。
- 本文は読みやすい日本語フォントスタックを使う。
- フォントファイルを無理に同梱しない。

### 12.3 タイトル画面

表示要素：

- CYCLE 6ロゴ文字
- 荷揚げ工程開始
- ランキング
- 設定
- フィクション表記

背景：

## 15. Master Concept生成指示

### 15.1 目的

master conceptは最終assetではなく、次を固定するための基準である。

- 色
- 光
- カメラ
- 設備のデザイン言語
- 海と空の雰囲気
- 画面の情報密度
- ゲームとしての読みやすさ

### 15.2 基準プロンプト

```text
PC向け2D工業シミュレーションゲーム「CYCLE 6」のmaster concept art。
寒冷な北日本の沿岸工業地域を想起させるが、実在施設を複製しない完全に架空の港湾。
横から見た16:9のサイドビュー、正投影に近い弱い遠近感。
左側に係留済みの架空専用船と船倉、中央上部に大型ガントリークレーン、右側に岸壁と陸上輸送車両の受台。
遠景には白と青緑を基調とした架空の大規模工業施設、低い曇天、薄い海霧、冷たい青灰色の海。
セミリアルな工業技術イラスト、現役で整備された設備、重量感のある金属、柔らかい曇天光。
ゲーム操作対象の輪郭が明確で、吊荷の移動経路が読みやすい構図。
サイバーパンク、宇宙基地、廃墟、軍事基地、実在企業ロゴ、人物、文字、数字を含めない。
```

### 15.3 修正時の優先順位

1. 横から見た操作の読みやすさ
2. 可動部の視認性
3. 船倉から受台までの空間
4. 寒冷地の空気感
5. 工業設備の説得力
6. 細部の豪華さ

細部を増やすことで操作対象が埋没する場合は、細部を減らす。

## 18. SVGデザイン指示

### 18.1 共通プロンプト相当

Codex等へ次を指示する。

```text
CYCLE 6の承認済みmaster conceptとpaletteに合わせ、2Dサイドビューの工業機械SVGを作る。
形は簡潔で重量感があり、ゲーム上の可動方向とpivotが明確であること。
SVGに文字、ロゴ、外部フォント、埋込みラスター画像を含めない。
物理コライダーは別管理するため、見た目を過度に単純化する必要はないが、細すぎる装飾を増やさない。
背景は透明とし、viewBoxとgroup idを整理する。
```

### 18.2 船体

- 横から見た架空専用船。
- 軍艦に見せない。
- 客船に見せない。
- 船倉位置が分かる。
- 船倉前景マスクを別ファイルへ分離する。
- 現実の特定船を複製しない。
- 船名文字をSVGへ入れない。

### 18.3 クレーン

- 大型港湾ガントリークレーン。
- 固定構造とトロリーを分離する。
- 可動レールが水平に読める。
- 軍港クレーンのような攻撃的デザインにしない。
- 主役は操作であり、装飾を増やしすぎない。

### 18.4 輸送容器

- 非常に重い円筒形または多角柱。
- 吊点が読み取れる。
- 上下方向が分かる。
- 揺れと角度を視認できる小さな非対称アクセントを付ける。
- 実在型式を複製しない。
- 警告文字を描かない。

### 18.5 搬送台車と受台

- 受台の中心とガイドが分かる。
- 後景部と前景部を分離する。
- 容器が正しく着座したことを視覚的に理解できる。
- 車輪、軸、サスペンションを過密に描かない。

## 19. アニメーション方針

### 19.1 フレームアニメーションを作らないもの

- 船体上下動
- 船体傾斜
- トロリー移動
- 巻上げ
- ワイヤー
- 吊荷揺れ
- 吹き流し
- 計器針
- 風筋
- 波しぶき
- 警告灯

これらはプログラムで動かす。

### 19.2 Tweenと物理の境界

- 物理対象の位置をTweenで動かさない。
- 船、吊具、容器、トロリーはWorker snapshotを使う。
- TweenはUI、フェード、ランプ、非物理背景に限定する。

### 19.3 画面揺れ

- 接触時に短く控えめに使う。
- 高波時も過度に揺らさない。
- SettingsでOFFにできる。
- 常時カメラを揺らさない。

## 20. 音響の視覚連携

音響制作そのものは別作業だが、デザインでは音の発生源を想定する。

必要な音：

- 海風
- 通常波
- 高波
- クレーンモーター
- 巻上げ装置
- ケーブル張力のきしみ
- ロック成立
- インターロック
- 軽い接触
- 着座
- 安全停止

音が重要な予兆を担う場合、視覚的な代替も必ず置く。

- 風音増加 ↔ 吹き流し、風筋
- 船体きしみ ↔ 動揺計、波頭
- 警報音 ↔ ランプ、アイコン

## 23. 制作ワークフロー

- クレーンレール位置
- 吊荷移動範囲
- 受台位置
- UI safe area

- 新しい案を乱造しない。

- master conceptと同じカメラ、光、paletteで作る。
- 可動部を除外する。
- greyboxの空間へ合わせる。

### Step 4: SVG制作

- Codexがmaster conceptとgreyboxを参照してSVGを作る。
- pivotとviewBoxを確認する。
- 仮コライダーとの位置を合わせる。

### Step 5: Phaser Effect

- 海
- 霧
- 風
- 波
- ワイヤー
- 計器

をプログラムで実装する。

### Step 6: 統合レビュー

確認する：

- 操作対象が背景へ埋没していないか。
- 船倉と受台が見えるか。
- 突風、高波の予兆が理解できるか。
- UIが吊荷を隠していないか。
- 21:9で不自然に伸びていないか。

## 27. 将来工程のデザイン規則

初期荷揚げ工程が完成した後も、同じ原則を使う。

### 道路運搬

- 背景はChatGPT。
- 車体と輸送容器はSVG。
- 路面、雨、風、ガイドはPhaser。
- フル3D車両にしない。

### せん断

- 機械本体はSVGまたは分割ラスター。
- 刃、送り装置、裁断片を分離する。
- 粉じん、振動、警告はPhaser。
- 実機寸法を再現しない。

### 溶解

- 槽本体はSVG。
- 液面、渦、泡はshader/particle。
- 本格流体を前提にした画像を作らない。
- 液体を緑に発光させない。

### 分離、精製、脱硝、ガラス固化、MOX

- 同じpaletteと線密度を継承する。
- 画面ごとに別ゲームのような画風へ変えない。
- 専門用語は実装側の文字として表示する。
- AI画像へラベルを焼き込まない。

## 28. 最終原則

ChatGPTは「全部入りの完成画面を一枚生成する役」ではない。

> ChatGPTは、背景、空気感、色、構図、工業デザインの基準を作る。Codexは、正確に動かす必要がある部品をSVGとして作る。Phaserは、物理状態に合わせてそれらを動かす。Reactは、文字と通常UIを担当する。

この分担により、ユーザーが手描きできなくても、形状ぶれ、pivot不明、文字崩れ、物理との不一致を抑えたゲーム制作を可能にする。美麗さより、操作対象が読みやすく、荷揚げが遊べることを優先する。
